# Documentation Standards

## Structure
- Lead with the most important information (inverted pyramid)
- Use logical heading hierarchy (h1 > h2 > h3, never skip levels)
- Keep paragraphs short - one idea per paragraph
- Use bullet lists for 3+ related items, numbered lists for sequential steps

## Writing Style
- Use active voice and imperative mood for instructions
- Be consistent in terminology - pick one term and stick with it
- Avoid jargon without definition; explain acronyms on first use
- Write for scanning: bold key terms, use meaningful headings

## Code Examples
- Provide complete, runnable examples rather than fragments
- Include expected output or result
- Show error cases alongside happy paths
- Use comments sparingly - only where the code isn't self-explanatory

## API Documentation
- Every endpoint needs: method, path, parameters, request body, response, error codes
- Include curl or equivalent examples for each endpoint
- Document authentication requirements upfront
- Show both success and error response examples

## README Files
- Start with: what it is, why it exists, how to get started
- Include: prerequisites, installation, quick start, configuration
- Link to detailed docs rather than duplicating content
- Keep the quick start under 5 steps

## Quality Checks
- Verify all links resolve correctly
- Test all code examples actually work
- Ensure consistent formatting throughout
- Check that instructions work from a clean starting point
